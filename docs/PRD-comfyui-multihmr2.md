# ComfyUI-MultiHMR2 视频人体 3D 重建插件 PRD

## 问题陈述

Multi-HMR 2 当前是独立的 Python 推理项目，主要通过 CLI/API 处理图片或视频。用户的主要场景是视频：在 ComfyUI 中加载视频，对视频内多人进行 3D 人体重建和跨帧跟踪，并输出可继续交给 VHS 编码的视频帧。

当前项目不能直接作为 ComfyUI 自定义节点使用，原因包括：输入输出不是 ComfyUI/VHS 数据契约、模型生命周期未接入 ComfyUI、分析与渲染耦合、没有缓存协议，也没有复用 ComfyUI 现有抠像模型的接口。

## 解决方案

在 `X:\ComfyUI-aki-v2\ComfyUI\custom_nodes\ComfyUI-MultiHMR2\` 创建 ComfyUI 自定义节点插件，复用现有 Multi-HMR 2 Python API，并增加 ComfyUI 适配层。

第一版以 VHS 视频帧为主要输入，拆分为两个节点：

1. `MultiHMR2 Video Analyze`：逐帧运行人体检测、3D 网格恢复和 Track ID 跟踪，生成可缓存的人体分析结果。
2. `MultiHMR2 Video Render`：读取原始帧和分析缓存，叠加网格、骨骼、Track ID、置信度等图层，处理背景，并输出 `IMAGE` 帧序列和 FPS。

推荐工作流：

```text
VHS Load Video
    ↓
MultiHMR2 Video Analyze
    ↓
MultiHMR2 Video Render
    ↓
VHS Video Combine
```

模型固定自动读取：

```text
X:\ComfyUI-aki-v2\ComfyUI\models\multihmr2\multihmr2.pt
```

分析缓存默认位于：

```text
X:\ComfyUI-aki-v2\ComfyUI\temp\multihmr2\
```

## 用户故事

1. 作为 ComfyUI 用户，我希望从 VHS 加载视频，并对视频中的多人进行逐帧 3D 人体重建，以便制作带人体 3D 效果的视频。
2. 作为视频创作者，我希望人物在整个视频中保持稳定的 Track ID，以便每个人使用稳定的颜色和显示效果。
3. 作为工作流用户，我希望分析结果缓存下来，以便反复调整渲染样式时不重复运行模型。
4. 作为用户，我希望自由组合网格、骨骼、ID、置信度、透明度和颜色等显示层。
5. 作为用户，我希望保留原视频音频，并通过 VHS 输出最终视频。
6. 作为用户，我希望使用 ComfyUI 已有的人像分割模型生成高质量透明背景，而不是插件重复管理一套抠像模型。
7. 作为用户，我希望长视频在显存不足时可以低分辨率或分段处理，而不是静默失败。
8. 作为后续 3D 工作流用户，我希望保留人体参数和相机数据，以便接入 Blender、动作分析或其他节点。

## 实现决策

### 节点与数据契约

- 以 VHS 的视频帧、FPS 和音频/元数据为输入来源。
- Analyze 输出一个插件内部的 `MultiHMR2Analysis` 缓存对象或缓存引用，不直接暴露大型逐帧 Python 对象给 UI。
- Render 输出 ComfyUI `IMAGE` 帧序列和 FPS，交给 VHS Video Combine 编码。
- 音频不由插件重新编码，由 VHS 负责保留和合并。
- 需要针对当前安装的 VHS 版本实现适配器，避免把 VHS 内部对象直接散落到后端逻辑。

### 分析行为

- 默认处理全部检测到的人物。
- 使用 Multi-HMR 2 的跨帧 tracker 生成稳定 Track ID。
- 暴露置信度阈值、3D NMS 距离阈值、低分辨率模式、分段长度和显存友好选项。
- 模型会话使用进程级/节点级单例或可复用缓存，不能每一帧重新加载 checkpoint。
- 模型只从固定默认路径读取，不提供用户自定义 checkpoint 路径。

### 渲染与背景

- 支持独立勾选：3D 网格、骨骼、Track ID、置信度、3D 框/地面位置。
- 支持人物颜色、透明度和 Track ID 筛选。
- 默认保留原背景。
- 支持透明背景和指定图片背景。
- 透明背景优先复用 ComfyUI 已有的高质量人像分割模型；插件提供分割适配接口。
- 没有可用分割模型时，必须明确报错或可选回退到网格投影遮罩，不得静默声称是高质量抠像。

### 缓存与长视频

- 缓存键至少包含输入视频标识、帧范围、分析参数、模型版本和插件版本。
- 缓存写入临时文件后再原子替换，避免中断产生不可用缓存。
- 支持自动清理缓存。
- 显存不足时支持低分辨率 Anny 模型和分段处理；分段需要正确处理帧序与 Track ID 连续性。
- Render 阶段只依赖缓存，不触发模型推理。

### 依赖与运行时

- 复用 ComfyUI 自带 Python 环境，不另建运行时。
- 必需依赖包括 `anny==0.6.0`、`roma`、`warp-lang`；透明/网格渲染能力可能需要 `pyrender`。
- 安装脚本必须使用 ComfyUI 自带 Python，并在安装前检查现有 Torch/CUDA 版本，避免覆盖 ComfyUI 的 PyTorch。
- 当前已知环境为 Python 3.12.10、PyTorch 2.11.0+cu130、CUDA 可用；依赖兼容性需要实际安装和启动测试确认。

## 验收标准

- ComfyUI 启动时插件可以导入，缺少依赖时显示可读的安装提示，不阻塞其他节点加载。
- 能从 VHS 视频输入完成一段短视频的 Analyze → Render → VHS Video Combine 流程。
- 模型只加载一次；重复执行渲染节点不会重新加载模型或重复分析。
- 输出帧数、分辨率和 FPS 与输入一致；最终由 VHS 编码时音频仍可保留。
- 同一人物在连续帧中 Track ID 稳定，人物颜色稳定。
- 可分别开关网格、骨骼、ID、置信度，并验证透明度生效。
- 分析缓存命中时不再次执行模型推理；修改渲染参数不会导致分析缓存失效。
- 高质量分割模型可被发现并调用；不可用时有明确状态提示。
- 显存不足路径可切换低分辨率或分段模式，并能完成输出。
- 失败任务清理临时文件，不能留下伪造的成功输出。

## 超出范围

- 不做文生视频、视频内容生成或人物动作生成。
- 第一版不支持用户手动画框指定人物。
- 不在插件内部固定绑定某一个抠像模型。
- 不把直接生成 MP4 作为主输出；主输出是 VHS 可继续处理的帧序列。
- 不在同一个节点中混合分析、渲染、编码全部逻辑。
- 不支持 AI 生成背景或动态视频背景。

## 进一步说明
